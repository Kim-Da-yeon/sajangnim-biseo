- 제안자명: 참가자 기입
- 팀원명: 참가자 기입(2명)

- 공모 분야: ③ 업무자동화·생산성
- 출품 주제: 공고 원문과 가게 정보를 대조해 근거와 함께 보여주는 소상공인 지원공고 확인 에이전트

## Ⅰ. 출품작 요약

| 항목 | 내용 |
|---|---|
| AI활용 주제 | 소상공인 지원공고 조건 대조 멀티에이전트와 온톨로지 기반 규칙 판정 |
| 해결하고자 하는 문제 | 지원공고마다 조건 표기가 다르고 분량이 길어(수집 공고 46건 평균 약 1.4만 자, 추출 텍스트 기준) 내 가게가 해당하는지 확인하기 어려움. 같은 '소기업' 매출 기준도 공고마다 다르게 적혀 있음(음식점 10억/15억 원 등. 현행 법령 기준은 미확인) |
| AI 활용·구현 방법 | Claude API로 문서 해석·근거 검증·진술 대조 등 6개 역할 에이전트 구성. RDF 온톨로지, SHACL 검증, 규칙 판정기 결합. Claude Code와 Codex를 개발·검수에 활용 |
| 주요 기능 및 결과물 | 입력 정보로 확인 가능한 공고 조건의 일치/불일치/확인 필요 표시, 조건별 원문 근거와 확인 가능한 쪽 번호, 필요한 질문만 묻기, 가게 설명 대조, 기관 판단 항목 표시, 마감일 달력 파일. 웹 시제품 |
| 현장 활용방안 | 사장님이 업종, 근로자 수, 매출, 개업일을 입력하면 공고상 신청기간 내 공고를 대조하고(조기 마감 가능성 표시), 근거를 확인한 뒤 공고 원문으로 이동. 정보 제공용이며 최종 자격은 주관기관이 판단 |
| 기대효과 | 공고 탐색·확인 시간 단축, 해당 없는 공고 신청 준비 비용 감소 기대. 효과 수치는 미측정 |

## Ⅱ. 세부 내용

### 1. 문제 정의 및 필요성

- 대상: 지원사업 공고를 직접 찾아 확인하는 소상공인·소공인, 예비창업자
- 수집 자료: 중소벤처기업부 사업공고와 기업마당 공고. 2026-11-02 수집
- 실제 공고에서 확인한 문제
  - 같은 소기업 매출 기준이 공고마다 다름: 음식점 생활문화 공고 15억 원, 고용보험료 공고 10억 원(현행 법령 기준 미확인)
  - 같은 공고 안의 표기 충돌: 보은군 공고의 소재지 조건 "본사, 공장 중 1개 이상"과 "본사, 공장 또는 사업장"
  - 일정 표기 오류: 보은군 공고 "10.22~10.5"
  - 다른 공고의 제외 업종을 참조하는 조건: 브랜드 공고가 정책자금 제외 업종 참조
- 범위: 공고 조건 대조 정보만 제공하며 법률 해석과 자격 확정은 제공하지 않음. 표현 제한만으로 법적 위험이 해소되는 것은 아니므로 외부 공개·유료화 전 전문가 검토 필요

### 2. AI 활용 및 구현 방법

| 구성 | 역할 |
|---|---|
| 총괄 에이전트 | 도구 호출 순서 결정, 재추출 지시, 추출 조건 채택 |
| 문서 해석 에이전트 | 공고에서 조건을 구조화. 근거 문구·쪽 번호 포함 |
| 근거 검증 에이전트 | 조건을 원문과 독립 대조. 지적의 원문 근거도 코드로 확인 |
| 진술 대조 에이전트 | 규칙으로 대조하기 어려운 조건을 사장님이 입력한 설명과 대조. 설명에 없는 문구를 근거로 든 결과는 코드로 폐기 |
| 프로필 인터뷰 에이전트 | 필요한 항목만 쉬운 질문으로 작성 |
| 안내 작성 에이전트 | 판정 결과를 안내문으로 작성. 금지 표현 검사 후 출력 |
| 온톨로지(RDF) | 업종 계층, 출처별 소기업 매출 기준, 제외 업종 코드 39개와 관련 예외 |
| SHACL·lint | 조건 구조 위반, 빈 값, 기간 누락, 인용 오류 검사 |
| 규칙 판정기 | 조건별 상태, OR 그룹, 기간 상태 계산. 온톨로지 조회 |

- 사용 도구
  - Claude API(claude-opus-5-5): 시스템 내 에이전트
  - Claude Code: 코드 작성, 데이터 수집, 평가 실행 보조
  - Codex CLI: 기획 검토, 정답 라벨 독립 감수
  - rdflib, pySHACL, FastAPI, matplotlib
- 데이터: 중소벤처기업부·기업마당 공개 공고. 가상 프로필만 사용. 개인정보·기업 내부 데이터 미사용

### 3. 주요 기능 및 결과물

사용자 흐름

1. 가게 정보 입력(선택: 가게 설명)
2. 공고별 대조 결과 확인. 일치/확인 필요/불일치로 구분
3. 질문 답변. 한 번 답하면 모든 공고에 반영, 상태 변화 표시
4. 공고를 펼쳐 조건별 근거 확인
5. 안내 받기, 공고 원문 이동, 마감일 달력 추가

| 비교군 | 공고 상태 일치 | 잘못된 일치 |
|---|---|---|
| 풀 시스템 | 19/24 | 1 |
| 온톨로지 제거 | 16/24 | 1 |
| 진술 대조 제거 | 10/24 | 0 |
| 단일 에이전트 | 10/24 | 0 |
| LLM 직접 응답 | 23/24 | 0 |

- 공고 상태 일치율은 LLM 직접 응답이 높았으며, 앞선 측정에서도 같았다
- 진술 대조는 기존 오답 10건을 바로잡고 SP6에서 오답 1건을 새로 만들어 순증 9건, 온톨로지는 순증 3건이었다
- 진술 대조 제거판과 단일 에이전트판의 공고 상태 일치는 각각 10/24로, 재검증 루프의 개선 효과는 관찰되지 않았다
- 측정 과정: 첫 평가 26/42(직접 응답 38/42), 1차 새 공고 15/30(직접 응답 24/30)에서 오답 원인을 찾아 개선. 이 공고들의 수정 후 수치는 사후 수치라 주 수치로 쓰지 않음
- 시스템이 직접 응답과 다른 점(측정치)
  - 반복 일관성: 각 3회 반복에서 직접 응답은 1차 30사례 중 3건, 진술 대조는 1차 30사례와 2차 24사례에서 0건 변경. 동일 표본의 전체 흐름 비교는 아님
  - 근거: 조건별 원문 문구와 확인 가능한 쪽 번호 제공. 2차 측정의 인용 오류 검출 0건(문구 존재 여부 기준)
  - 비용 구조(토큰×단가 추정): 직접 응답 1회 약 $0.067, 조건 확정 공고당 약 $0.5, 진술 대조 1회 약 $0.009. 규칙 판정에는 LLM 호출 없음

### 4. 현장 활용방안 및 기대효과

- 활용: 소상공인 지원센터, 상인회, 세무·행정 상담 창구에서 공고 1차 확인용으로 사용 가능
- 기대효과: 공고 탐색 시간 단축, 해당 없는 공고 준비 비용 감소, 놓치는 공고 감소. 실제 효과 수치는 미측정이며 사장님 대상 테스트를 다음 단계로 계획
- 비용 예시(공고 46건 가정, 추정): 직접 응답은 사용자당 약 $3.1. 시스템은 조건 확정에 약 $23이 1회 발생하고, 규칙 판정의 추가 LLM 비용은 없음. 46건 모두 진술 대조를 1회씩 수행하면 사용자당 약 $0.41 추가

### 5. 향후 발전 및 확산 계획

- 실제 사장님 테스트로 입력 부담, 이해도, 시간 절감 측정
- 공고 자동 수집과 조건 확정 자동화. 정정 공고 비교
- 규칙으로 표현 가능한 조건 확대(OR 안의 AND, 재보증 제한 목록)
- 시스템이 놓친 사례를 줄이도록 직접 응답과 교차 확인하는 방식 검토
- 지자체·상인회 공고, 다른 업종 지원제도로 확대

### 한계 고지

- 정답 라벨은 AI 초안과 Codex 감수 후 참가자가 애매한 조항을 확인함. 참가자 수정(5사례)은 전체 점수를 본 뒤 반영했고 시스템은 다시 실행하지 않음. 수정 전 주 수치는 풀 시스템 20/24, 직접 응답 24/24. 전문가 검증은 받지 않음
- 프로필은 가상이며 표본이 작아 공고 전반의 정확도가 아님
- 프로필의 자유 문장은 AI가 작성해 LLM 계열에 유리할 수 있음
- 2차 24사례 중 1건(SP6)에서 정답 '확인 필요'를 '일치'로 표시함. 실제 신청 자격은 주관기관에 확인해야 함
